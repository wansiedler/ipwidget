# App Store release checklist

Branch `appstore` builds the sandboxed variant (`SWIFT_ACTIVE_COMPILATION_CONDITIONS = APPSTORE`).
The local developer build (`./build.sh`, launchd agent, ip-api.com over HTTP, rebuild-from-source) stays on `feature/ip-widget`.

## What differs in the APPSTORE build

| Area | Local build | App Store build |
|---|---|---|
| IP provider | ip-api.com (HTTP, non-commercial licence) | ipwho.is (HTTPS, commercial OK, 10k req/month) → ipinfo.io fallback |
| DNS-leak check | edns.ip-api.com over HTTP | same — ATS exception for `ip-api.com` + subdomains stays; justify in review notes (service has no HTTPS on the free tier) or buy ip-api Pro ($13/mo, HTTPS) |
| Gateway / VPN names | `route`, `scutil` child processes | `SCDynamicStore` (works in the sandbox, no processes) — Network-Extension VPNs that do not publish `State:/Network/Service/*/IPv4` (e.g. Amnezia AWG) are not listed |
| Autostart | launchd LaunchAgent | `SMAppService.mainApp` — menu item "Запускать при входе" |
| Self-update | menu item runs `git pull` + `build.sh` | removed |
| Wi‑Fi SSID | always attempted | opt-in flag; requests Location (When In Use); entitlement `personal-information.location` |
| Signing | ad-hoc | Automatic, team AR4T8G5N3D, hardened runtime, sandbox |

## Project

```bash
xcodegen generate                                   # project.yml → IPWidget.xcodeproj (git-ignored)
xcodebuild -project IPWidget.xcodeproj -scheme IPWidget -configuration Release \
  -derivedDataPath build/DerivedData build          # local sandboxed test build
open build/DerivedData/Build/Products/Release/IPWidget.app
```

Files: `project.yml`, `IPWidget.entitlements`, `PrivacyInfo.xcprivacy`, `Assets.xcassets/AppIcon.appiconset` (generated by `tools/make-icon.swift`), `Info.plist` (shared with the local build).

## Before submitting

1. **Apple Developer Program** ($99/yr) active for team AR4T8G5N3D; Xcode → Settings → Accounts signed in.
2. **App Store Connect**: create app "IP Widget", bundle id `com.wansiedler.ipwidget`, category Utilities, price (suggest $4.99 one-time).
3. **Privacy**: App Privacy → "Data Not Collected" is wrong — the IP is sent to third parties for geolocation. Declare *Data Not Linked to You → Identifiers → IP address? No: Apple classifies it under "Other Usage Data" / "Precise/Coarse Location: Coarse".* Pick **Coarse Location – App Functionality – Not linked**. Write a privacy policy URL (one page: what is sent, to whom, nothing stored by developer).
4. **Review notes**: explain the ATS exception (edns.ip-api.com has no HTTPS on the free tier, only used to detect which DNS resolver answers), the Location permission (SSID only), the desktop-level window (not a WidgetKit widget; it is a normal window pinned to the desktop layer), and the Carbon hotkey.
5. **Screenshots**: 1280×800 or 2560×1600; widget on the desktop (normal + large), the ⚙ menu, DNS-leak state, menu bar item. Mask real IP with "Маскировать IP".
6. **Archive**: Xcode → Product → Archive (or `xcodebuild archive … && xcodebuild -exportArchive -exportOptionsPlist` with `method: app-store`), upload via Organizer or Transporter.
7. **Version**: bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `project.yml`, re-run `xcodegen`.

## Known review risks

- Guideline 4.2 (minimum functionality): mitigated by the feature set; the icon + About panel + login item make it look like a real app.
- Guideline 5.1.1: Location prompt must only appear after the user enables the SSID flag (it does).
- Third-party API quotas: ipwho.is 10k/month ≈ 30 s interval × 12 h/day exceeds it (~43k). For the store default the interval to 5 min, or ship with a paid key. **TODO before release.**
- Speed test uses an undocumented Cloudflare endpoint; label it "experimental" in the description.
- Notifications: the app requests authorization at first launch; acceptable, but consider requesting only when the user turns on "Уведомлять о смене IP".
